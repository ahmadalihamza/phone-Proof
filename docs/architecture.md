# Architecture

PhoneProof has one Android application with target and scanner modes, a FastAPI modular monolith, PostgreSQL in deployment, a Redis/Celery inference boundary, and S3-compatible private storage. SQLite is supported for local API development and tests. The two Gradle modules separate platform diagnostics and their contracts from application UI/persistence/networking. Feature packages isolate scanner, guided tests, account and reports. This first implementation does not create empty modules for unimplemented enterprise features.

The shared JSON registry defines IDs, versions, handlers, prerequisites, timeouts, methods, weights and criteria. Python generates its reference table. Camera templates expand only over CameraManager-exposed IDs. Disabled definitions never become performed results. Metadata has weight zero. A category count is secondary to individual expandable rows.

Android writes an immutable attempt to Room before enqueueing WorkManager. Result UUIDs remain unchanged across retries. Only a matching server acknowledgement marks an attempt synced. Data is retained after rejection. Account and backend-origin bindings prevent a later login/server switch from uploading an old inspection to the wrong owner. A new attempt is appended on retry. The current result is the latest completed attempt; history remains in both databases.

Backend inspection creation is idempotent by client UUID. Capability/registry snapshots are fixed once bound. Raw results validate definition IDs/versions and require evidence for PASS/FAIL. The server applies its own weights, computes coverage, preserves exclusions, and caps critical failures. Finalization locks the account and inspection, checks required evidence, consumes an entitlement in the same transaction, signs canonical JSON and stores the immutable report. Database triggers protect audit, raw results, reports and revocations. Revocation adds a record instead of editing the signed payload.

Pairing uses a hashed, expiring, single-use random token. The scanner signs in to the same account; organization delegation is a later feature. The token binds a scanner installation ID and fresh capture nonce. CameraX captures into app-private files; a durable queue uploads them. Server image QC checks real pixel data, strips metadata and compares perceptual hashes. A human must confirm all twelve views and any cosmetic annotations. No pretrained generic model is treated as a crack/scratch model.

The signature establishes integrity of the stored inspection report, not independent truth of every client claim. Play Integrity attestation and device-matrix validation remain release gates. A malicious client can lie about its own hardware evidence; the product must not imply that signing alone prevents this.

Account email actions queue encrypted delivery records in the same database transaction as their hashed, expiring code. A separate SMTP worker retries delivery and erases terminal payloads. Password reset changes the password, advances session version and revokes refresh tokens atomically. Android API clients share an in-flight refresh coordinator; the token vault applies a response only when the requesting session is still current. Login/logout change the local session generation, while refresh rotation preserves it.

Manual and background synchronization share a coroutine mutex. Each run captures a session generation and backend origin before identifying its owner. Every authenticated request verifies that scope; an account/server change stops the run before selecting new credentials. Owner bindings and capture filters use the captured origin. Requests already authorized retain their original token and server, while refresh within the same generation is permitted. A later login can resume only its own bound queue entries.
